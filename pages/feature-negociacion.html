Negociación de Presupuesto

Propuestas de precios en el chat con botones interactivos de aceptar/rechazar e integración de depósito de garantía

Descripción General

La negociación de presupuestos en iMirly se realiza directamente en la interfaz de chat. Los proveedores de servicios pueden enviar propuestas de presupuesto como burbujas de mensaje especiales con botones de acción integrados, lo que permite a los clientes aceptarlas, pagarlas o solicitar revisiones sin problemas.

Flujo de Usuario

1

Proveedor envía presupuesto

El proveedor de servicios toca el ícono de presupuesto en el chat e ingresa el precio total y una descripción opcional.

2

Cliente revisa propuesta

El cliente ve una burbuja de presupuesto amarilla con el precio claramente visible y botones de acción.

3

Cliente decide

El cliente puede: Aceptar y pagar (el dinero va al depósito en garantía) o Rechazar y solicitar una nueva cotización.

4

Actualizaciones de estado

Tras la aceptación, el contrato pasa al estado PAGADO y el proveedor puede comenzar a trabajar.

@Composable
fun ChatInputBar(
    viewModel: ChatViewModel, 
    otroUsuarioId: String,

    soyElProveedor: Boolean, 
    primaryColor: Color
) {
    var showDialogPrecio by remember { mutableStateOf(false) }

                         tint = primaryColor)
                }
            }
            
            OutlinedTextField(
                value = viewModel.inputText.value,
                onValueChange = { viewModel.inputText.value = it },
                placeholder = { Text("Escribe un mensaje...") },
                modifier = Modifier.weight(1f)
            )
            
            FloatingActionButton(
                onClick = { viewModel.enviarMensaje(otroUsuarioId) },
                containerColor = primaryColor
            ) {
                Icon(Icons.Default.Send, contentDescription = "Enviar")
            }
        }
    }
    
    // Diálogo de presupuesto
    if (showDialogPrecio) {
        AlertDialog(
            onDismissRequest = { showDialogPrecio = false },
            title = { Text("Enviar Presupuesto") },
            text = {
                Column {
                    OutlinedTextField(
                        value = precioTemp,
                        onValueChange = { precioTemp = it },
                        label = { Text("Precio total (€)") },
                        keyboardOptions = KeyboardOptions(
                            keyboardType = KeyboardType.Number
                        )
                    )
                    Spacer(modifier = Modifier.height(8.dp))
                    OutlinedTextField(
                        value = descTemp,
                        onValueChange = { descTemp = it },
                        label = { Text("Descripción (opcional)") },
                        maxLines = 3
                    )
                }
            },
            confirmButton = {
                Button(onClick = {
                    val finalString = "$precioTemp|$descTemp"
                    viewModel.enviarPresupuesto(otroUsuarioId, solicitudId, finalString)
                    showDialogPrecio = false
                    precioTemp = ""
                    descTemp = ""
                }) { Text("Enviar") }
            }
        )
    }
}

Envío de Propuesta de Presupuesto

Kotlin
ChatViewModel.kt 
fun enviarPresupuesto(
    receptorId: String, 
    solicitudId: String, 
    presupuestoContenido: String
) {
    if (presupuestoContenido.isBlank() || presupuestoContenido.startsWith("|")) return
    
    viewModelScope.launch {
        try {
            val request = EnviarMensajeRequest(
                receptorId = receptorId,
                contenido = presupuestoContenido, // Formato: "50.0|Descripción"
                solicitudId = solicitudId,
                tipo = "PROPUESTA_PRECIO"
            )
            val response = RetrofitClient.mensajeService.enviarMensaje(request)
            if (response.isSuccessful) {
                cargarConversacion(receptorId)
            }
        } catch (e: Exception) {
            Log.e("ChatViewModel", "Error sending budget", e)
        }
    }
}

Aceptar y Pagar

Kotlin
ChatViewModel.kt 
fun aceptarYPagar(solicitudId: String, otroUsuarioId: String) {
    viewModelScope.launch {
        try {
            val responsePago = RetrofitClient.solicitudService
                .pagarSolicitud(solicitudId)
            
            if (responsePago.isSuccessful) {
                val requestMsg = EnviarMensajeRequest(
                    receptorId = otroUsuarioId,
                    contenido = "He aceptado el presupuesto y he realizado el pago. El dinero está retenido de forma segura en iMirly. Ya puedes empezar el trabajo.",
                    solicitudId = solicitudId,
                    tipo = "PRESUPUESTO_ACEPTADO"
                )
                RetrofitClient.mensajeService.enviarMensaje(requestMsg)
                cargarConversacion(otroUsuarioId)
            }
        } catch (e: Exception) {
            Log.e("ChatViewModel", "Error accepting budget", e)
        }
    }
}

Rechazando el Presupuesto

Kotlin
ChatViewModel.kt 
fun rechazarPresupuesto(solicitudId: String, otroUsuarioId: String) {
    viewModelScope.launch {
        try {
            val requestEstado = CambiarEstadoRequest("ACEPTADO")
            val response = RetrofitClient.solicitudService
                .cambiarEstadoSolicitud(solicitudId, requestEstado)
            
            if (response.isSuccessful) {
                val requestMsg = EnviarMensajeRequest(
                    receptorId = otroUsuarioId,
                    contenido = "He rechazado la oferta. Por favor, revisa el precio y envíame un nuevo presupuesto.",
                    solicitudId = solicitudId,
                    tipo = "PRESUPUESTO_RECHAZADO"
                )
                RetrofitClient.mensajeService.enviarMensaje(requestMsg)
                cargarConversacion(otroUsuarioId)
            }
        } catch (e: Exception) {
            Log.e("ChatViewModel", "Error rejecting budget", e)
        }
    }
}

Implementación Backend

Gestión del Estado del Contrato

Las propuestas presupuestarias actualizan el estado del contrato:

Java
SolicitudContrato.java 
public class SolicitudContrato {
    private UUID id;
    private UUID clienteId;
    private UUID proveedorId;
    private UUID anuncioId;
    private EstadoSolicitud estado;
    private Double precioAcordado;
    
    // Proveedor propone precio
    public void proponerPrecio(Double precio) {
        this.precioAcordado = precio;
        this.estado = EstadoSolicitud.PENDIENTE_PAGO;
    }
    
    // Cliente acepta y paga
    public void pagarPresupuesto() {
        if (this.estado != EstadoSolicitud.PENDIENTE_PAGO) {
            throw new IllegalStateException(
                "Solo se puede pagar una solicitud pendiente de pago."
            );
        }
        this.estado = EstadoSolicitud.PAGADO;
    }
}

Estados del Contrato

PENDIENTE

Solicitud inicial

ACEPTADO

Proveedor aceptó

EN_CURSO

Trabajo en progreso

COMPLETADO

Trabajo completado y pagado

RECHAZADO

Solicitud rechazada

PENDIENTE_PAGO

Presupuesto enviado, esperando pago

PAGADO

Pagado, dinero en depósito

REVISION_PENDIENTE

Trabajo hecho, esperando aprobación del cliente

Manejo del Presupuesto del Servicio de Mensajes

Cuando se envía un mensaje de presupuesto, el servicio actualiza el contrato:

Java
MensajeService.java 
@Transactional
public Mensaje enviarMensaje(EnviarMensajeCommand command) {
    if (command.getTipo() == TipoMensaje.PROPUESTA_PRECIO) {
        actualizarSolicitudConPrecio(command);
    }
    
    Mensaje nuevoMensaje = new Mensaje(
        command.getRemitenteId(),
        command.getReceptorId(),
        command.getSolicitudId(),
        command.getContenido(),
        command.getTipo()
    );
    
    return repositoryPort.save(nuevoMensaje);
}

private void actualizarSolicitudConPrecio(EnviarMensajeCommand command) {
    SolicitudContrato solicitud = solicitudRepositoryPort
        .findById(command.getSolicitudId())
        .orElseThrow(() -> new IllegalArgumentException("Solicitud no encontrada"));
    
    try {
        // Parsear formato "50.0|Descripción"
        String[] partes = command.getContenido().split("\\|");
        Double precio = Double.parseDouble(partes[0].trim());
        
        solicitud.proponerPrecio(precio);
        solicitudRepositoryPort.save(solicitud);
    } catch (Exception e) {
        throw new IllegalArgumentException("El formato del presupuesto es incorrecto.");
    }
}

@PostMapping("/{id}/pagar")
public ResponseEntity pagarSolicitud(@PathVariable UUID id) {
    try {
        String tokenUserId = SecurityContextHolder.getContext()
            .getAuthentication().getCredentials();
        UUID clienteId = UUID.fromString(tokenUserId);
        
        SolicitudContrato pagada = useCase.pagarSolicitud(id, clienteId);
        return ResponseEntity.ok(pagada);
    } catch (IllegalArgumentException | IllegalStateException e) {
        return ResponseEntity.badRequest().body(e.getMessage());
    }
}

Procesamiento de Pagos con Depósito en Garantía

Java
SolicitudContratoService.java 
@Service
public class SolicitudContratoService {
    
    @Override
    @Transactional
    public SolicitudContrato pagarSolicitud(UUID solicitudId, UUID clienteId) {
        // 1. Buscar contrato
        SolicitudContrato solicitud = repositoryPort.findById(solicitudId)
            .orElseThrow(() -> new IllegalArgumentException("Solicitud no encontrada."));
        
        // 2. Verificar que el cliente es dueño del contrato
        if (!solicitud.getClienteId().equals(clienteId)) {
            throw new IllegalStateException(
                "No tienes permiso para pagar esta solicitud."
            );
        }
        
        // 3. Obtener usuario cliente
        User cliente = userRepository.findById(clienteId)
            .orElseThrow(() -> new IllegalArgumentException("Cliente no encontrado."));
        
        // 4. Deducir saldo y crear transacción
        cliente.restarSaldo(solicitud.getPrecioAcordado());
        userRepository.save(cliente);
        
        TransaccionEntity tr = new TransaccionEntity(
            null, cliente.getId(), 
            solicitud.getPrecioAcordado(), 
            "SERVICIO_PAGADO",
            "Pago de presupuesto en iMirly", 
            LocalDateTime.now()
        );
        transaccionRepository.save(tr);
        
        // 5. Actualizar estado del contrato a PAGADO (dinero en depósito)
        solicitud.pagarPresupuesto();
        return repositoryPort.save(solicitud);
    }
}
Depósito en Garantía

El dinero se retiene en depósito (el contrato indica "PAGADO") hasta que el cliente aprueba el trabajo finalizado. El proveedor no recibe el pago hasta que el cliente confirma su satisfacción.

Diseño Visual

Apariencia de la Burbuja Presupuestaria

  • Fondo: Amarillo suave (#FFF9E6) para resaltar
  • Cabecera: "Presupuesto Acordado" en oro (#FFB800)
  • Precio: Texto grande y en negrita (24sp) en negro
  • Descripción: Texto gris más pequeño debajo del precio
  • Botones: Ancho completo, apilados verticalmente
  • Sombra: Elevación de 4dp para prominencia

Indicadores de Respuesta

Una vez que se responde a un presupuesto:

  • Aceptado: Aparece el mensaje verde "Presupuesto Aceptado"
  • Rechazado: Aparece mensaje rojo "Presupuesto Rechazado"
  • La burbuja presupuestaria original muestra el texto "Oferta respondida" en gris
  • Los botones de acción están ocultos para evitar acciones duplicadas

La interfaz de usuario detecta de forma inteligente si se ha respondido a un presupuesto comprobando si hay mensajes más nuevos con tipos distintos de TEXTO, lo que evita respuestas duplicadas.

Manejo de Errores

Saldo Insuficiente

Si el cliente no tiene saldo suficiente:

Java
User.java 
public void restarSaldo(Double cantidad) {
    if (cantidad == null || cantidad <= 0) {
        throw new IllegalArgumentException(
            "La cantidad a restar debe ser mayor que cero."
        );
    }
    if (this.saldo == null) this.saldo = 0.0;
    this.saldo -= cantidad;
}

Los clientes deben tener saldo suficiente antes de aceptar un presupuesto. Si no tienen saldo suficiente, deben agregar fondos a través de la función Monedero Virtual.

Puntos de Integración

  • Mensajes: Las propuestas de presupuesto son tipos de mensajes especiales
  • Monedero Virtual: El pago se descuenta del saldo del cliente
  • Gestión de Tareas: Los cambios en el estado del contrato habilitan el flujo de trabajo
  • Historial de Transacciones: Los pagos aparecen en el historial de la billetera
