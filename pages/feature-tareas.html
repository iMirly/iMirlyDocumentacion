Gestión de Tareas

Ciclo de vida completo del servicio desde la solicitud hasta la aprobación con flujos de trabajo controlados por estado e integración de depósito en garantía

Descripción General

El sistema de gestión de tareas de iMirly gestiona todo el ciclo de vida de la prestación de servicios mediante una máquina de estados que garantiza la correcta progresión del flujo de trabajo. Los contratos pasan por etapas bien definidas, desde la solicitud inicial hasta su finalización, con el dinero depositado en garantía como garantía.

Estados del Ciclo de Vida del Servicio

Java
EstadoSolicitud.java 
public enum EstadoSolicitud {
    PENDIENTE,          // Client sent initial request
    ACEPTADO,           // Provider accepted the request
    EN_CURSO,           // Work in progress
    COMPLETADO,         // Work completed and payment released
    RECHAZADO,          // Request rejected by provider
    PENDIENTE_PAGO,     // Budget sent, awaiting client payment
    PAGADO,             // Client paid, money in escrow
    REVISION_PENDIENTE  // Provider marked work done, awaiting approval
}

Flujo de Usuario Completo

1

Servicio de Solicitudes de Clientes

El cliente explora las listas de servicios, selecciona un proveedor y envía una solicitud de contrato con detalles sobre lo que necesita.

2

Solicitud de Reseñas de Proveedores

El proveedor recibe la solicitud en su bandeja de entrada y puede aceptarla o rechazarla.

3

Negociación Presupuestaria

El proveedor envía una propuesta de presupuesto por chat. El cliente puede aceptarla y pagarla o rechazarla y solicitar una revisión.

4

Pago a Depósito en Garantía

Al ser aceptado, se deduce el saldo del cliente y el dinero se retiene en depósito en garantía (estado PAGADO).

5

Ejecución de Obra

El proveedor completa el trabajo mientras el dinero permanece seguro en depósito en garantía.

6

Presentación de Trabajos

El proveedor marca el trabajo como terminado (REVISION_PENDIENTE), activando un mensaje especial con botones de aprobación.

7

Aprobación del Cliente

El cliente revisa y aprueba (libera el pago) o rechaza (solicita correcciones).

8

Liberación de Pago

Tras la aprobación, los fondos de depósito en garantía se agregan al saldo del proveedor y el contrato pasa a COMPLETADO.

Modelo de Dominio Contractual

Java
SolicitudContrato.java 
@Getter
@Setter
public class SolicitudContrato {
    private UUID id;
    private UUID clienteId;
    private UUID proveedorId;
    private UUID anuncioId;
    private EstadoSolicitud estado;
    private String detallesSolicitud;
    private Double precioAcordado;
    private LocalDateTime fechaCreacion;
    private String nombreProveedor;
    private String nombreCliente;
    
    // Initial state constructor
    public SolicitudContrato(UUID clienteId, UUID anuncioId, String detallesSolicitud) {
        this.clienteId = clienteId;
        this.anuncioId = anuncioId;
        this.detallesSolicitud = detallesSolicitud;
        this.estado = EstadoSolicitud.PENDIENTE;
        this.fechaCreacion = LocalDateTime.now();
    }
    
    // State transition methods
    public void aceptar() {
        if (this.estado == EstadoSolicitud.PENDIENTE) {
            this.estado = EstadoSolicitud.ACEPTADO;
        } else {
            throw new IllegalStateException(
                "Solo se pueden aceptar solicitudes pendientes."
            );
        }
    }
    
    public void proponerPrecio(Double precio) {
        this.precioAcordado = precio;
        this.estado = EstadoSolicitud.PENDIENTE_PAGO;
    }
    
    public void pagarPresupuesto() {
        if (this.estado != EstadoSolicitud.PENDIENTE_PAGO) {
            throw new IllegalStateException(
                "Solo se puede pagar una solicitud pendiente de pago."
            );
        }
        this.estado = EstadoSolicitud.PAGADO;
    }
    
    public void marcarComoTerminado() {
        this.estado = EstadoSolicitud.REVISION_PENDIENTE;
    }
    
    public void validarTrabajo(boolean esBueno) {
        if (esBueno) {
            this.estado = EstadoSolicitud.COMPLETADO;
        } else {
            this.estado = EstadoSolicitud.PAGADO; // Back to in-progress
        }
    }
}

Servicio por Contrato

Java
SolicitudContratoService.java 
@Service
@RequiredArgsConstructor
public class SolicitudContratoService implements SolicitudContratoUseCase {
    
    private final SolicitudContratoRepositoryPort repositoryPort;
    private final UserRepositoryPort userRepository;
    private final TransaccionRepository transaccionRepository;
    
    @Override
    public SolicitudContrato crearSolicitud(CrearSolicitudCommand command) {
        anuncioRepositoryPort.findById(command.getAnuncioId())
            .orElseThrow(() -> new IllegalArgumentException("El anuncio no existe."));
        
        SolicitudContrato nueva = new SolicitudContrato(
            command.getClienteId(),
            command.getAnuncioId(),
            command.getDetalles()
        );
        return repositoryPort.save(nueva);
    }
    
    @Override
    public SolicitudContrato cambiarEstado(CambiarEstadoSolicitudCommand command) {
        SolicitudContrato solicitud = repositoryPort
            .findById(command.getSolicitudId())
            .orElseThrow(() -> new IllegalArgumentException("Solicitud no encontrada."));
        
        if (command.getNuevoEstado() == EstadoSolicitud.RECHAZADO) {
            repositoryPort.deleteById(solicitud.getId());
            solicitud.setEstado(EstadoSolicitud.RECHAZADO);
            return solicitud;
        }
        
        if (command.getNuevoEstado() == EstadoSolicitud.ACEPTADO) {
            if (solicitud.getEstado() == EstadoSolicitud.PENDIENTE) {
                solicitud.aceptar();
            } else if (solicitud.getEstado() == EstadoSolicitud.PENDIENTE_PAGO) {
                solicitud.setEstado(EstadoSolicitud.ACEPTADO);
            }
        } else {
            solicitud.setEstado(command.getNuevoEstado());
            
            // Release escrow when work is completed
            if (command.getNuevoEstado() == EstadoSolicitud.COMPLETADO) {
                User proveedor = userRepository.findById(solicitud.getProveedorId())
                    .orElseThrow();
                proveedor.sumarSaldo(solicitud.getPrecioAcordado());
                userRepository.save(proveedor);
                
                TransaccionEntity tr = new TransaccionEntity(
                    null, proveedor.getId(), 
                    solicitud.getPrecioAcordado(), 
                    "SERVICIO_COBRADO",
                    "Cobro por trabajo en iMirly", 
                    LocalDateTime.now()
                );
                transaccionRepository.save(tr);
            }
        }
        
        return repositoryPort.save(solicitud);
    }
}

Cambios de Estado del Servicio de Mensajes

Los tipos de mensajes especiales desencadenan cambios de estado:

Java
MensajeService.java 
@Service
public class MensajeService implements MensajeUseCase {
    
    @Override
    @Transactional
    public Mensaje enviarMensaje(EnviarMensajeCommand command) {
        // Handle work completion message
        if (command.getTipo() == TipoMensaje.TRABAJO_FINALIZADO) {
            SolicitudContrato solicitud = solicitudRepositoryPort
                .findById(command.getSolicitudId())
                .orElseThrow();
            solicitud.marcarComoTerminado();
            solicitudRepositoryPort.save(solicitud);
        } 
        // Handle work approval
        else if (command.getTipo() == TipoMensaje.SERVICIO_COMPLETADO) {
            solicitudContratoUseCase.cambiarEstado(
                new CambiarEstadoSolicitudCommand(
                    command.getSolicitudId(), 
                    EstadoSolicitud.COMPLETADO, 
                    command.getRemitenteId()
                )
            );
        } 
        // Handle work rejection
        else if (command.getTipo() == TipoMensaje.SERVICIO_RECHAZADO) {
            SolicitudContrato solicitud = solicitudRepositoryPort
                .findById(command.getSolicitudId())
                .orElseThrow();
            solicitud.validarTrabajo(false); // Revert to PAGADO
            solicitudRepositoryPort.save(solicitud);
        }
        
        Mensaje nuevoMensaje = new Mensaje(
            command.getRemitenteId(),
            command.getReceptorId(),
            command.getSolicitudId(),
            command.getContenido(),
            command.getTipo()
        );
        
        return repositoryPort.save(nuevoMensaje);
    }
}

Validación y Seguridad

Validación de Transición de Estado

El modelo de dominio impone transiciones de estado válidas:

Java
SolicitudContrato.java 
public void aceptar() {
    if (this.estado == EstadoSolicitud.PENDIENTE) {
        this.estado = EstadoSolicitud.ACEPTADO;
    } else {
        throw new IllegalStateException(
            "Solo se pueden aceptar solicitudes pendientes."
        );
    }
}

Esto evita operaciones no válidas como:

  • Aceptar un contrato ya completado
  • Pagar por un contrato que no ha sido presupuestado
  • Marcar el trabajo como terminado antes del pago

Protección contra la Eliminación de Chat

Los contratos con pagos activos no se pueden eliminar:

Java
SolicitudContratoService.java 
public void eliminarSolicitud(UUID id) {
    SolicitudContrato solicitud = repositoryPort.findById(id)
        .orElseThrow();
    
    // Block deletion if money is involved
    if (solicitud.getEstado() == EstadoSolicitud.PENDIENTE_PAGO ||
        solicitud.getEstado() == EstadoSolicitud.PAGADO ||
        solicitud.getEstado() == EstadoSolicitud.EN_CURSO ||
        solicitud.getEstado() == EstadoSolicitud.REVISION_PENDIENTE) {
        throw new IllegalStateException(
            "No se puede borrar el chat si hay un presupuesto aceptado."
        );
    }
    
    repositoryPort.deleteById(id);
}
Protección Financiera

Esta protección garantiza que los usuarios no puedan eliminar accidentalmente contratos con dinero en depósito, lo que evita disputas financieras.
