Mensajería en Tiempo Real

Comunicación fluida entre clientes y proveedores con polling automático y confirmaciones de lectura

Visión General

iMirly proporciona un sistema de chat en tiempo real que permite la comunicación directa entre clientes y proveedores de servicios. El sistema de mensajería realiza polling automático cada 3 segundos e incluye confirmaciones de lectura, tipos de mensajes y gestión de conversaciones.

Flujo de Usuario

1

Acceder al Inbox

Los usuarios navegan a la pestaña Mensajes donde ven todas las solicitudes de contrato activas y conversaciones en curso.

2

Abrir Conversación

Toca una tarjeta de contrato para abrir el chat con la otra parte (cliente o proveedor).

3

Enviar Mensajes

Escribe mensajes en el campo de entrada y toca enviar. Los mensajes aparecen instantáneamente con estado de entrega en tiempo real.

4

Recibir Actualizaciones

El chat se actualiza automáticamente cada 3 segundos para obtener nuevos mensajes sin interacción del usuario.

Implementación Android

Componente de Pantalla de Chat

La interfaz de chat está construida con Jetpack Compose e incluye polling automático:

Kotlin
ChatScreen.kt 
@Composable
fun ChatScreen(
    navController: NavController,
    otroUsuarioId: String,
    nombreContacto: String,
    solicitudId: String,
    soyElProveedor: Boolean,
    viewModel: ChatViewModel = viewModel()
) {
    // Iniciar polling automático cuando carga la pantalla
    DisposableEffect(otroUsuarioId) {
        viewModel.startPolling(otroUsuarioId)
        onDispose { viewModel.stopPolling() }
    }
    
    Scaffold(
        topBar = { /* Cabecera del chat con nombre del contacto */ },
        bottomBar = { ChatInputBar(viewModel, otroUsuarioId, solicitudId, soyElProveedor) }
    ) { paddingValues ->
        LazyColumn(
            modifier = Modifier.fillMaxSize().padding(paddingValues),
            reverseLayout = true
        ) {
            itemsIndexed(mensajesReversed) { index, mensaje ->
                val isMine = mensaje.remitenteId != otroUsuarioId
                ChatBubble(mensaje = mensaje, isMine = isMine)
            }
        }
    }
}

Polling Automático

Los mensajes se obtienen automáticamente usando corrutinas de Kotlin:

Kotlin
ChatViewModel.kt 
fun startPolling(otroUsuarioId: String) {
    pollingJob?.cancel()
    pollingJob = viewModelScope.launch {
        while (isActive) {
            cargarConversacion(otroUsuarioId)
            delay(3000) // Poll cada 3 segundos
        }
    }
}

fun stopPolling() {
    pollingJob?.cancel()
}

private suspend fun cargarConversacion(otroUsuarioId: String) {
    try {
        val response = RetrofitClient.mensajeService.obtenerConversacion(otroUsuarioId)
        if (response.isSuccessful) {
            mensajes.value = response.body() ?: emptyList()
        }
    } catch (e: Exception) {
        Log.e("ChatViewModel", "Error cargando conversación", e)
    }
}

Envío de Mensajes

Kotlin
ChatViewModel.kt 
fun enviarMensaje(receptorId: String) {
    val texto = inputText.value.trim()
    if (texto.isEmpty()) return
    
    // Limpiar input inmediatamente para feedback instantáneo
    inputText.value = ""
    
    viewModelScope.launch {
        try {
            val request = EnviarMensajeRequest(receptorId, texto)
            val response = RetrofitClient.mensajeService.enviarMensaje(request)
            if (response.isSuccessful) {
                cargarConversacion(receptorId) // Recargar para mostrar mensaje enviado
            }
        } catch (e: Exception) {
            Log.e("ChatViewModel", "Error enviando mensaje", e)
        }
    }
}

Enviar Mensaje

POST /api/v1/mensajes Java
MensajeController.java 
@PostMapping
public ResponseEntity enviarMensaje(@RequestBody EnviarMensajeRequest request) {
    String emailRemitente = SecurityContextHolder.getContext()
        .getAuthentication().getPrincipal();
    
    UserEntity usuario = userRepository.findByEmail(emailRemitente)
        .orElseThrow(() -> new RuntimeException("Usuario no encontrado"));
    
    EnviarMensajeCommand command = new EnviarMensajeCommand(
        usuario.getId(),
        request.getReceptorId(),
        request.getSolicitudId(),
        request.getContenido(),
        request.getTipo() != null ? request.getTipo() : TipoMensaje.TEXTO
    );
    
    Mensaje guardado = useCase.enviarMensaje(command);
    return ResponseEntity.status(HttpStatus.CREATED).body(toResponse(guardado));
}

Obtener Conversación

GET /api/v1/mensajes/conversacion/{otroUsuarioId}

Marca automáticamente los mensajes como leídos al recuperarlos:

Java
MensajeController.java 
@GetMapping("/conversacion/{otroUsuarioId}")
public ResponseEntity obtenerConversacion(@PathVariable UUID otroUsuarioId) {
    String emailActual = SecurityContextHolder.getContext()
        .getAuthentication().getPrincipal();
    
    UserEntity usuario = userRepository.findByEmail(emailActual)
        .orElseThrow(() -> new RuntimeException("Usuario no encontrado"));
    
    List conversacion = useCase
        .obtenerConversacion(usuario.getId(), otroUsuarioId)
        .stream()
        .map(this::toResponse)
        .collect(Collectors.toList());
    
    return ResponseEntity.ok(conversacion);
}

El backend marca automáticamente los mensajes como leídos cuando un usuario recupera la conversación vía repositoryPort.marcarMensajesComoLeidos(otroUsuarioId, usuarioActualId).

public ResponseEntity borrarConversacion(@PathVariable UUID otroUsuarioId) {
    String emailActual = SecurityContextHolder.getContext()
        .getAuthentication().getPrincipal();

Lógica de Negocio del Servicio

El servicio de mensajes maneja tipos de mensajes especiales y dispara cambios de estado:

Java
MensajeService.java 
@Service
public class MensajeService implements MensajeUseCase {
    
    @Override
    @Transactional
    public Mensaje enviarMensaje(EnviarMensajeCommand command) {
        if (command.getContenido() == null || command.getContenido().trim().isEmpty()) {
            throw new IllegalArgumentException("El mensaje no puede estar vacío.");
        }
        
        // Manejar tipos de mensajes especiales
        if (command.getTipo() == TipoMensaje.PROPUESTA_PRECIO) {
            actualizarSolicitudConPrecio(command);
        } else if (command.getTipo() == TipoMensaje.TRABAJO_FINALIZADO) {
            SolicitudContrato solicitud = solicitudRepositoryPort
                .findById(command.getSolicitudId())
                .orElseThrow();
            solicitud.marcarComoTerminado();
            solicitudRepositoryPort.save(solicitud);
        } else if (command.getTipo() == TipoMensaje.SERVICIO_COMPLETADO) {
            solicitudContratoUseCase.cambiarEstado(
                new CambiarEstadoSolicitudCommand(
                    command.getSolicitudId(), 
                    EstadoSolicitud.COMPLETADO, 
                    command.getRemitenteId()
                )
            );
        }
        
        // Crear y guardar el mensaje
        Mensaje nuevoMensaje = new Mensaje(
            command.getRemitenteId(),
            command.getReceptorId(),
            command.getSolicitudId(),
            command.getContenido(),
            command.getTipo()
        );
        
        return repositoryPort.save(nuevoMensaje);
    }
}

Características de la UI

Burbujas de Chat

Los mensajes se muestran con diferentes estilos según el remitente y tipo:

  • Mis mensajes: Fondo morado, alineados a la derecha
  • Mensajes del otro: Fondo blanco, alineados a la izquierda
  • Mensajes especiales: Fondo amarillo (propuestas de presupuesto, finalización de trabajo)

Actualizaciones en Tiempo Real

El mecanismo de polling asegura:

  • Nuevos mensajes aparecen dentro de 3 segundos
  • Las confirmaciones de lectura se actualizan automáticamente
  • No se necesita refresco manual
  • Eficiente en batería (se detiene al salir de la pantalla)
Optimización de Batería

El polling se detiene automáticamente cuando el usuario navega fuera de la pantalla de chat, previniendo el consumo innecesario de batería y datos.

Integración con Otras Características

El sistema de mensajería está estrechamente integrado con:

  • Negociación de Presupuesto: Burbujas de mensajes especiales para propuestas de precio
  • Gestión de Tareas: Los cambios de estado disparan mensajes
  • Monedero Virtual: Las confirmaciones de pago aparecen en el chat
  • Sistema de Valoraciones: Las valoraciones post-servicio se envían como mensajes

Consulta la página de Negociación de Presupuesto para más detalles sobre tipos de mensajes especiales.
