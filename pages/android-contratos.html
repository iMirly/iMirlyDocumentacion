Contratos y Pagos

Gestiona solicitudes de servicios y pagos basados en escrow en la aplicación iMirly Android

Visión General

El sistema de contratos y pagos de iMirly maneja el ciclo de vida completo de las solicitudes de servicio:

  • El cliente crea la solicitud (Solicitud)
  • El profesional envía propuesta de precio
  • El cliente acepta y paga (fondos retenidos en escrow)
  • El profesional completa el trabajo
  • El cliente aprueba y libera el pago
  • El cliente valora al profesional

API Interface
network/SolicitudApiService.kt 
package com.imirly.app.network

import retrofit2.Response
import retrofit2.http.*

data class CrearSolicitudRequest(
    val anuncioId: String,
    val detalles: String
)

data class SolicitudResponse(
    val id: String,
    val clienteId: String,
    val anuncioId: String,
    val estado: String,
    val detallesSolicitud: String,
    val fechaCreacion: String,
    val nombreCliente: String? = "Cliente",
    val proveedorId: String? = null,
    val nombreProveedor: String? = "Profesional",
    var soyElProveedor: Boolean = false
)

data class CambiarEstadoRequest(
    val nuevoEstado: String
)

interface SolicitudApiService {
    @POST("/api/v1/solicitudes")
    suspend fun crearSolicitud(
        @Body request: CrearSolicitudRequest
    ): Response

    @GET("/api/v1/solicitudes/proveedor")
    suspend fun getSolicitudesProveedor(): Response>

    @GET("/api/v1/solicitudes/cliente")
    suspend fun getSolicitudesCliente(): Response>

    @PATCH("/api/v1/solicitudes/{id}/estado")
    suspend fun cambiarEstadoSolicitud(
        @Path("id") id: String,
        @Body request: CambiarEstadoRequest
    ): Response

    @DELETE("/api/v1/solicitudes/{id}")
    suspend fun eliminarSolicitud(@Path("id") id: String): Response

    @POST("/api/v1/solicitudes/{id}/pagar")
    suspend fun pagarSolicitud(@Path("id") id: String): Response
}

Crear Solicitudes de Servicio

Desde Pantalla de Detalle

Cuando un usuario ve un anuncio de servicio, puede contactar al profesional:

ui/catalog/AnuncioDetailViewModel.kt 
package com.imirly.app.ui.catalog

import androidx.compose.runtime.mutableStateOf
import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import com.imirly.app.network.CrearSolicitudRequest
import com.imirly.app.network.RetrofitClient
import kotlinx.coroutines.launch

class AnuncioDetailViewModel : ViewModel() {
    var showContactDialog = mutableStateOf(false)
    var mensajeContacto = mutableStateOf("")
    var isSubmitting = mutableStateOf(false)
    var requestSuccess = mutableStateOf(false)

    fun enviarSolicitud(anuncioId: String) {
        if (mensajeContacto.value.isBlank()) return

        isSubmitting.value = true
        viewModelScope.launch {
            try {
                val request = CrearSolicitudRequest(
                    anuncioId = anuncioId,
                    detalles = mensajeContacto.value
                )
                val response = RetrofitClient.solicitudService.crearSolicitud(request)

                if (response.isSuccessful) {
                    requestSuccess.value = true
                } else {
                    println("Error del servidor: ${response.code()}")
                }
            } catch (e: Exception) {
                println("Fallo crítico en Retrofit: ${e.message}")
                e.printStackTrace()
            } finally {
                isSubmitting.value = false
            }
        }
    }
}

Estados del Ciclo de Vida

La solicitud pasa por varios estados:

1

PENDIENTE

Estado inicial cuando el cliente crea la solicitud

2

ACEPTADO

El profesional ha revisado y enviado propuesta de precio

3

PAGADO

El cliente aceptó la propuesta y pagó (fondos en escrow)

4

COMPLETADO

El profesional marcó el trabajo como completado

5

FINALIZADO

El cliente aprobó el trabajo y liberó el pago

ViewModel
ui/messages/MessagesViewModel.kt 
package com.imirly.app.ui.messages

import androidx.compose.runtime.mutableStateOf
import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import com.imirly.app.network.RetrofitClient
import com.imirly.app.network.SolicitudResponse
import com.imirly.app.network.TokenManager
import kotlinx.coroutines.launch

class MessagesViewModel : ViewModel() {
    var solicitudes = mutableStateOf>(emptyList())
    var isLoading = mutableStateOf(true)

    fun cargarSolicitudes() {
        isLoading.value = true
        viewModelScope.launch {
            try {
                // Cargar solicitudes como cliente y como proveedor
                val respCliente = RetrofitClient.solicitudService.getSolicitudesCliente()
                val respProveedor = RetrofitClient.solicitudService.getSolicitudesProveedor()

                val listCliente = if (respCliente.isSuccessful) {
                    respCliente.body() ?: emptyList()
                } else emptyList()

                val listProveedor = if (respProveedor.isSuccessful) {
                    respProveedor.body()?.map { it.copy(soyElProveedor = true) } ?: emptyList()
                } else emptyList()

                solicitudes.value = listCliente + listProveedor
            } catch (e: Exception) {
                // Manejar error
            } finally {
                isLoading.value = false
            }
        }
    }
}

fun MessagesScreen(navController: NavController, viewModel: MessagesViewModel = viewModel()) {

    }

            Box(modifier = Modifier.fillMaxSize(), contentAlignment = Alignment.Center) {

            Box(modifier = Modifier.fillMaxSize(), contentAlignment = Alignment.Center) {
                Text("No tienes conversaciones activas", color = Color.Gray)
            }
        } else {
            LazyColumn {
                items(viewModel.solicitudes.value) { solicitud ->
                    ConversationCard(
                        solicitud = solicitud,
                        onClick = {
                            val otroUsuarioId = if (solicitud.soyElProveedor) {
                                solicitud.clienteId
                            } else {
                                solicitud.proveedorId ?: ""
                            }
                            val nombreOtroUsuario = if (solicitud.soyElProveedor) {
                                solicitud.nombreCliente ?: "Cliente"
                            } else {
                                solicitud.nombreProveedor ?: "Profesional"
                            }
                            navController.navigate(
                                "chat/$otroUsuarioId/$nombreOtroUsuario/${solicitud.id}"
                            )
                        }
                    )
                    Spacer(modifier = Modifier.height(12.dp))
                }
            }
        }
    }
}

Procesamiento de Pagos

Pago en Escrow

Cuando un cliente acepta una propuesta, los fondos se retienen en escrow:

Pago en Escrow 
fun aceptarYPagar(solicitudId: String, otroUsuarioId: String) {
    viewModelScope.launch {
        try {
            val responsePago = RetrofitClient.solicitudService.pagarSolicitud(solicitudId)

            if (responsePago.isSuccessful) {
                // Enviar mensaje de notificación
                val requestMsg = EnviarMensajeRequest(
                    receptorId = otroUsuarioId,
                    contenido = "He aceptado el presupuesto y he realizado el pago. El dinero está retenido de forma segura en iMirly. Ya puedes empezar el trabajo.",
                    solicitudId = solicitudId,
                    tipo = "PRESUPUESTO_ACEPTADO"
                )
                RetrofitClient.mensajeService.enviarMensaje(requestMsg)
                
                // Recargar conversación
                cargarConversacion(otroUsuarioId)
            } else {
                // Manejar error de pago
                when (responsePago.code()) {
                    400 -> println("Saldo insuficiente")
                    404 -> println("Solicitud no encontrada")
                    else -> println("Error de pago: ${responsePago.code()}")
                }
            }
        } catch (e: Exception) {
            android.util.Log.e("ChatViewModel", "Excepción crítica al pagar", e)
        }
    }
}

El endpoint de pago verifica el saldo del usuario antes de procesar. Asegúrate de que los usuarios tengan fondos suficientes cargados.

fun marcarTrabajoFinalizado(receptorId: String, solicitudId: String) {
    viewModelScope.launch {
        try {
            val requestMsg = EnviarMensajeRequest(
                receptorId = receptorId,
                contenido = "He marcado el trabajo como finalizado. Por favor, revísalo y confirma si todo está correcto para liberar el pago.",
                solicitudId = solicitudId,
                tipo = "TRABAJO_FINALIZADO"
            )
            val msgResponse = RetrofitClient.mensajeService.enviarMensaje(requestMsg)
            if (msgResponse.isSuccessful) cargarConversacion(receptorId)
        } catch (e: Exception) {
            android.util.Log.e("ChatViewModel", "Error finalizando", e)
        }
    }
}

        try {

                contenido = "He revisado el trabajo y está perfecto. Pago liberado, ¡muchas gracias!",

                tipo = "SERVICIO_COMPLETADO"

                cargarConversacion(receptorId)
                // El pago se libera al profesional
            }
        } catch (e: Exception) {
            android.util.Log.e("ChatViewModel", "Error aprobando", e)
        }
    }
}

Borrar Conversaciones

Borrar Chat y Solicitud 
fun borrarChatYSolicitud(
    otroUsuarioId: String,
    solicitudId: String,
    onSuccess: () -> Unit,
    onError: (String) -> Unit
) {
    viewModelScope.launch {
        try {
            // El backend protege el borrado si hay fondos retenidos
            val response = RetrofitClient.solicitudService.eliminarSolicitud(solicitudId)

            if (response.isSuccessful) {
                // Borrar mensajes
                RetrofitClient.mensajeService.borrarConversacion(otroUsuarioId)
                onSuccess()
            } else {
                onError("No se puede borrar este chat porque hay un presupuesto en curso o pagado.")
            }
        } catch (e: Exception) {
            onError("Error de conexión al intentar borrar el chat.")
        }
    }
}

El backend previene el borrado de conversaciones con pagos activos para proteger a ambas partes.

Probar Contratos y Pagos

  1. Crear Solicitud

    Como cliente, ve un servicio y envía una solicitud de contacto.

  2. Enviar Propuesta

    Como profesional, envía una propuesta de precio en el chat.

  3. Aceptar y Pagar

    Como cliente, acepta la propuesta y verifica que los fondos se retienen.

  4. Completar Trabajo

    Como profesional, marca el trabajo como completado.

  5. Aprobar y Liberar

    Como cliente, aprueba el trabajo y verifica que el pago se libera.

  6. Valorar Profesional

    Como cliente, envía una valoración (1-5 estrellas).

Consideraciones de Seguridad

Notas Importantes de Seguridad:
  • Todas las operaciones de pago requieren autenticación (JWT)
  • El sistema escrow previene transferencias directas
  • El backend valida saldo suficiente antes del pago
  • Las solicitudes con fondos retenidos no pueden borrarse
  • Solo el cliente puede liberar el pago tras aprobación
