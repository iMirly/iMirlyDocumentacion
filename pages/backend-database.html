Gestión de Esquema

La aplicación utiliza la función auto-DDL de Hibernate:

Modo Comportamiento
create Elimina y recrea las tablas al iniciar
create-drop Crea tablas al iniciar, las elimina al cerrar
update Actualiza el esquema para coincidir con las entidades (añade columnas, nunca elimina)
validate Valida que el esquema coincida con las entidades (recomendado para producción)
none Sin gestión de esquema
Producción

En producción: Usa siempre validate o none y gestiona el esquema con herramientas de migración como Flyway o Liquibase.

@Entity
@Table(name = "usuarios")
@Getter
@Setter

    private boolean verificado;

    @Column(name = "fecha_registro")
    private LocalDateTime fechaRegistro;

    @Column(name = "saldo", columnDefinition = "DECIMAL(10,2) DEFAULT 0.0")
    private Double saldo;

    @Column(name = "puntuacion_total", columnDefinition = "DOUBLE PRECISION DEFAULT 0.0")
    private Double puntuacionTotal = 0.0;

    @Column(name = "numero_valoraciones", columnDefinition = "INTEGER DEFAULT 0")
    private Integer numeroValoraciones = 0;
}

Mapeo de Enum

El enum UserType se almacena como cadena en la base de datos:

Java
Mapeo de Enum 
@Enumerated(EnumType.STRING)
@Column(name = "tipo_usuario")
private UserType tipo;

Valores posibles:

  • PROFESIONAL - Proveedor de servicios
  • CLIENTE - Consumidor de servicios

Usar EnumType.STRING en lugar de EnumType.ORDINAL hace la base de datos más legible y resistente a reordenamientos del enum.

Adaptador de Repositorio

El adaptador traduce entre modelos de dominio y entidades JPA:

Java
UserRepositoryAdapter.java 
@Repository
@RequiredArgsConstructor
public class UserRepositoryAdapter implements UserRepositoryPort {
    
    private final SpringDataUserRepository springDataRepository;
    private final UserMapper userMapper;

    @Override
    public User save(User user) {
        // 1. Dominio → Entidad
        UserEntity entity = userMapper.toEntity(user);
        // 2. Guardar en base de datos
        UserEntity savedEntity = springDataRepository.save(entity);
        // 3. Entidad → Dominio
        return userMapper.toDomain(savedEntity);
    }

    @Override
    public Optional findByEmail(String email) {
        return springDataRepository.findByEmail(email)
                .map(userMapper::toDomain);
    }

    @Override
    public boolean existsByEmail(String email) {
        return springDataRepository.existsByEmail(email);
    }

    @Override
    public Optional findById(UUID id) {
        return springDataRepository.findById(id)
                .map(userMapper::toDomain);
    }
}

Modelo de Dominio vs Entidad

Modelo de Dominio (Java Puro)

Java
User.java 
@Getter
@Setter
public class User {
    private UUID id;
    private String nombre;
    private String email;
    private String passwordHash;
    private UserType tipo;
    private String documentoIdentidad;
    private boolean verificado;
    private LocalDateTime fechaRegistro;
    private Double saldo;
    private Double puntuacionTotal;
    private Integer numeroValoraciones;

    // Lógica de negocio en el modelo de dominio
    public void restarSaldo(Double cantidad) {
        if (cantidad == null || cantidad <= 0) {
            throw new IllegalArgumentException("La cantidad a restar debe ser mayor que cero.");
        }
        if (this.saldo == null)
            this.saldo = 0.0;
        this.saldo -= cantidad;
    }

    public void sumarSaldo(Double cantidad) {
        if (cantidad == null || cantidad <= 0) {
            throw new IllegalArgumentException("La cantidad a sumar debe ser mayor que cero.");
        }
        if (this.saldo == null)
            this.saldo = 0.0;
        this.saldo += cantidad;
    }

    public Double getValoracionMedia() {
        if (numeroValoraciones == null || numeroValoraciones == 0)
            return 0.0;
        return Math.round((puntuacionTotal / numeroValoraciones) * 10.0) / 10.0;
    }
}

Sin anotaciones JPA, solo lógica de negocio pura.

Separación Crítica

Los modelos de dominio contienen la lógica de negocio, las entidades son solo contenedores de datos para persistencia.

Desde AnuncioServicio.java:

Java
AnuncioServicio.java 
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
public class AnuncioServicio {
    private UUID id;
    private UUID proveedorId; // Referencia a Usuario
    private UUID subcategoriaId; // Referencia a subcategoría
    private String titulo;
    private String descripcion;
    private BigDecimal precioHora;
    private String ubicacion;
    private boolean activo;
    private String nombreProfesional;
    private Double valoracionProfesional;
    private Integer numeroValoracionesProfesional;

    // Constructor para nuevos anuncios
    public AnuncioServicio(UUID proveedorId, UUID subcategoriaId, String titulo, 
                          String descripcion, BigDecimal precioHora, String ubicacion) {
        this.proveedorId = proveedorId;
        this.subcategoriaId = subcategoriaId;
        this.titulo = titulo;
        this.descripcion = descripcion;
        this.precioHora = precioHora;
        this.ubicacion = ubicacion;
        this.activo = true;
        this.valoracionProfesional = 0.0;
        this.numeroValoracionesProfesional = 0;
    }

    // Lógica de negocio
    public void pausarAnuncio() {
        this.activo = false;
    }

    public void reactivarAnuncio() {
        this.activo = true;
    }
}

Gestión de Transacciones

Spring gestiona automáticamente las transacciones para las clases @Service:

Java
Gestión de Transacciones 
@Service
@Transactional // Todos los métodos ejecutan en una transacción
public class ManageAnuncioService implements ManageAnuncioUseCase {
    
    @Override
    public AnuncioServicio publicarAnuncio(CreateAnuncioCommand command) {
        // Este método completo ejecuta en una sola transacción
        User user = userRepositoryPort.findById(command.getProveedorId())
                .orElseThrow(() -> new IllegalArgumentException("Usuario no encontrado"));
        
        AnuncioServicio anuncio = new AnuncioServicio(...);
        return anuncioRepositoryPort.save(anuncio);
        
        // Si ocurre cualquier excepción, la transacción se revierte
    }
}

Añade @Transactional a métodos que necesiten atomicidad. Por defecto, Spring revierte la transacción en RuntimeException.

Anotaciones JPA Útiles

Anotación Propósito Ejemplo
@Entity Marca una clase como entidad JPA @Entity
@Table Especifica el nombre de la tabla @Table(name = "usuarios")
@Id Clave primaria @Id
@GeneratedValue Generación automática de ID @GeneratedValue(strategy = GenerationType.UUID)
@Column Mapeo de columna @Column(name = "password_hash")
@Enumerated Estrategia de almacenamiento de enum @Enumerated(EnumType.STRING)
@Temporal Mapeo de fecha/hora @Temporal(TemporalType.TIMESTAMP)
@ManyToOne Relación muchos a uno @ManyToOne
@OneToMany Relación uno a muchos @OneToMany(mappedBy = "user")
