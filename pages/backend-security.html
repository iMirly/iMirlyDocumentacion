Arquitectura de Seguridad

El backend de iMirly utiliza JWT (JSON Web Tokens) para autenticación stateless con Spring Security.

Flujo de autenticación: Cliente → AuthController → LoginService → PasswordEncoder/JwtTokenAdapter → Base de Datos

Configuración de Spring Security

Desde SecurityConfig.java:

Java
SecurityConfig.java 
@Configuration
@EnableWebSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtAuthFilter;

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
                .csrf(csrf -> csrf.disable())
                .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
                .authorizeHttpRequests(auth -> auth
                        // Endpoints públicos
                        .requestMatchers("/api/v1/auth/**").permitAll()
                        .requestMatchers("/api/v1/dev/**").permitAll()
                        // Todos los demás endpoints requieren autenticación
                        .anyRequest().authenticated())
                .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);

        return http.build();
    }
}

CSRF está deshabilitado porque los tokens JWT no son vulnerables a ataques CSRF (no se almacenan en cookies).

Política de Sesión

Java
Configuración Stateless 
.sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))

STATELESS significa:

  • No se crean sesiones HTTP
  • No se usan cookies para autenticación
  • Cada petición debe incluir el token JWT
  • Perfecto para APIs REST y microservicios

Encriptación de Contraseñas

BCrypt Password Encoder

Desde BasicPasswordEncoderAdapter.java:

Java
BasicPasswordEncoderAdapter.java 
@Component
@RequiredArgsConstructor
public class BasicPasswordEncoderAdapter implements PasswordEncoderPort {

    private final PasswordEncoder springPasswordEncoder;

    @Override
    public String encode(String rawPassword) {
        // Hash BCrypt con generación automática de salt
        return springPasswordEncoder.encode(rawPassword);
    }

    @Override
    public boolean matches(String rawPassword, String encodedPassword) {
        // Comparación segura que previene ataques de timing
        return springPasswordEncoder.matches(rawPassword, encodedPassword);
    }
}

¿Por qué BCrypt?

Lento por Diseño

Deliberadamente lento para hacer ataques de fuerza bruta impracticables

Salt Automático

Cada contraseña obtiene un salt único, previniendo ataques de rainbow table

Adaptativo

El factor de costo puede aumentar a medida que el hardware mejora

Estándar de la Industria

Algoritmo ampliamente utilizado y probado en producción

Flujo de Contraseña

1

Registro de Usuario

Java 
// Usuario proporciona: "MiContraseñaSegura123"
String rawPassword = "MiContraseñaSegura123";

// BCrypt genera hash con salt
String hash = passwordEncoder.encode(rawPassword);
// Resultado: "$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy"

// Almacenar hash en base de datos (nunca la contraseña en texto plano)
user.setPasswordHash(hash);
userRepository.save(user);
2

Login de Usuario

Java 
// Usuario proporciona: "MiContraseñaSegura123"
String rawPassword = "MiContraseñaSegura123";

// Obtener hash almacenado de la base de datos
String storedHash = user.getPasswordHash();
// "$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy"

// BCrypt verifica haciendo hash de la entrada y comparando
boolean isValid = passwordEncoder.matches(rawPassword, storedHash);
// true - ¡contraseñas coinciden!
Importante

Nunca almacenes contraseñas en texto plano ni uses encriptación reversible. BCrypt es una función de hash unidireccional.

Implementación de Token JWT

Generación de Token

Desde JwtTokenAdapter.java:

Java
JwtTokenAdapter.java 
@Component
public class JwtTokenAdapter implements TokenProviderPort {

    private final Key SECRET_KEY = Keys.secretKeyFor(SignatureAlgorithm.HS256);
    private final long EXPIRATION_TIME = 86400000; // 24 horas en milisegundos

    @Override
    public String generateToken(User user) {
        return Jwts.builder()
                .setSubject(user.getEmail())
                .claim("id", user.getId())
                .claim("tipo", user.getTipo().name())
                .setIssuedAt(new Date())
                .setExpiration(new Date(System.currentTimeMillis() + EXPIRATION_TIME))
                .signWith(SECRET_KEY)
                .compact();
    }
}

Validación de Token

Desde JwtTokenAdapter.java:

Java
Validación de Token 
public boolean validateToken(String token) {
    try {
        Jwts.parserBuilder()
            .setSigningKey(SECRET_KEY)
            .build()
            .parseClaimsJws(token);
        return true;
    } catch (Exception e) {
        return false; // Token inválido, expirado o malformado
    }
}

Extracción de Claims

Java
Extracción de Claims 
public String getEmailFromToken(String token) {
    return Jwts.parserBuilder().setSigningKey(SECRET_KEY).build()
            .parseClaimsJws(token).getBody().getSubject();
}

public String getIdFromToken(String token) {
    return Jwts.parserBuilder().setSigningKey(SECRET_KEY).build()
            .parseClaimsJws(token).getBody().get("id", String.class);
}

Filtro de Autenticación JWT

Desde JwtAuthenticationFilter.java:

Java
JwtAuthenticationFilter.java 
@Component
@RequiredArgsConstructor
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private final JwtTokenAdapter jwtTokenAdapter;

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
            throws ServletException, IOException {
        
        // 1. Extraer token del header Authorization
        String authHeader = request.getHeader("Authorization");
        String token = null;

        if (authHeader != null && authHeader.startsWith("Bearer ")) {
            token = authHeader.substring(7); // Eliminar prefijo "Bearer "
        }

        // 2. Validar token y autenticar usuario
        if (token != null && jwtTokenAdapter.validateToken(token)) {
            String email = jwtTokenAdapter.getEmailFromToken(token);
            String userId = jwtTokenAdapter.getIdFromToken(token);

            // Crear objeto de autenticación
            UsernamePasswordAuthenticationToken authentication = new UsernamePasswordAuthenticationToken(
                    email, userId, new ArrayList<>()
            );
            SecurityContextHolder.getContext().setAuthentication(authentication);
        }

        // 3. Continuar cadena de filtros
        filterChain.doFilter(request, response);
    }
}

Flujo del filtro: Request → ¿Tiene header Authorization? → ¿Empieza con Bearer? → Extraer token → ¿Token válido? → Establecer autenticación → Siguiente filtro

Flujo del Filtro

SÍ → Establece autenticación
NO → Continúa sin autenticación

OncePerRequestFilter asegura que el filtro se ejecute exactamente una vez por petición, incluso con forwards/includes.

OncePerRequestFilter asegura que el filtro se ejecute exactamente una vez por petición, incluso con forwards/includes.

@Override
public String login(LoginUserCommand command) {
    // Buscar usuario
    User user = userRepositoryPort.findByEmail(command.getEmail())
            .orElseThrow(() -> new IllegalArgumentException("Credenciales inválidas"));

    // Verificar contraseña
    if (!passwordEncoderPort.matches(command.getRawPassword(), user.getPasswordHash())) {
        throw new IllegalArgumentException("Credenciales inválidas");
    }

    // Generar token
    return tokenProviderPort.generateToken(user);
}

public ResponseEntity getProfile() {

Mejores Prácticas de Seguridad

Gestión de Clave Secreta

Almacena la clave secreta en variables de entorno, nunca en el código fuente. Usa algoritmos fuertes (HS256 o superior).

Expiración de Token

Mantén los tokens con vida corta (15-60 minutos). Implementa refresh tokens para sesiones largas sin comprometer seguridad.

HTTPS en Producción

Siempre usa HTTPS en producción para proteger los tokens en tránsito. Los tokens son credenciales sensibles.

Rate Limiting

Implementa límites de peticiones en endpoints de autenticación para prevenir ataques de fuerza bruta.

Problemas de Seguridad Comunes

XSS (Cross-Site Scripting)

No almacenes JWT en localStorage en el frontend. Usa cookies httpOnly o almacenamiento en memoria.

Robo de Token

Si un token es robado, es válido hasta su expiración. Implementa revocación/blacklisting de tokens para operaciones sensibles.
